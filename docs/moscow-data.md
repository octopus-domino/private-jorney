# Московские сведения о доме (1.0.9)

В 1.0.10 при отсутствии известного точного адреса сначала запрашиваются контуры 60562 и определяется выбранное здание.
Ошибка Photon больше не блокирует обращение к официальному адресному реестру. Reverse-geocoding используется только если реестр не дал однозначного совпадения;
известный адрес по-прежнему сопоставляется с локальным индексом без лишнего сетевого запроса.

Источники: [официальная документация](https://data.mos.ru/developers/documentation),
[набор 2681](https://data.mos.ru/opendata/2681), [адресный реестр 60562](https://data.mos.ru/opendata/60562).
Новые сведения встроены в существующую вкладку «О доме», в том числе для обычного нажатия на карту.
История «Узнай Москву» и поиск всех мест интереса через codoc.site сохранены.

## Поиск и актуальные данные

Компактный публичный справочник адресов и UNOM создаётся `scripts/refresh-moscow-index.py` из проекции официального API.
Он содержит ссылки на 34 472 дома, адреса и управляющие организации, без контактов и персональных полей.
В APK справочник используется только для точного сопоставления выбранного адреса, а не для поиска точек интереса.
Телефон не скачивает весь городской реестр: запрашивает строку организации для конкретного UNOM и проверяет его в ответе.
Если порядок строк изменился, выполняется поиск организации по официальному имени с повторной проверкой UNOM.
При неоднозначном адресе используется контур здания из адресного реестра. Земельные участки исключены.
Неподтверждённый соседний дом не показывается вместо выбранного.

Год, этажность, серия проекта, число подъездов и лифтов адаптируются существующей сводкой.
Нули и отсутствующие значения не выводятся. В наборе 2681 нет опубликованных характеристик жителей,
материалов конструкций, износа и выполненного капремонта: эти сведения не выводятся и не угадываются по серии дома.
Ссылка в технической карточке ведёт на официальный набор-источник; историческая карточка сохраняет ссылку на статью о доме.

## Дополнительный источник ремонта

Подключён официальный [набор 62963 «Работы по капитальному ремонту многоквартирных домов»](https://data.mos.ru/opendata/62963).
Проверка каталога и схем API 18.11.2026 также охватила наборы 3293 (счета капремонта), 1537 (план фасадных работ 2014 года),
2387 (агрегированная статистика строительства), 520 (паспортизация отдельных новостроек), 60562 и публичную карточку dom.mos.ru.
Счета и исторические планы не трактуются как выполненные работы; статистика района не переносится на жителей выбранного дома.
Износ, материалы лестниц, коммунальные квартиры и возрастной состав жителей в этих проверенных схемах на уровне выбранного дома не найдены.

`scripts/refresh-moscow-repair-index.py` формирует компактный UNOM -> положение строки + global_id из публичной проекции API.
Текущий индекс: 3714 строк работ, 2393 адресных кода, версия набора 2.877. Это ограниченный опубликованный набор, а не вся история ремонта Москвы.
Индекс загружается отдельным ленивым модулем. Выбранные страницы по 250 строк запрашиваются последовательно с фиксированной версией,
чтобы смещение строк не подменило запись; принадлежность проверяется повторно по global_id и UNOM. Обновление покрытия требует обновления индекса.
Поля договоров, подрядчиков и контакты в результирующий кеш не попадают.

В общей сводке дома появились блоки крыши, водоснабжения/канализации, отопления, электрики, фасада и других элементов,
только когда для них опубликованы работы. Показываются статус и фактические/плановые даты. Просроченный план не становится выполненным ремонтом.
Год ремонта не превращается в оценку износа и не доказывает полную замену элемента. Общая, жилая и нежилая площади из 2681 также отображаются при положительных значениях.

Успешный результат ремонта кешируется на сутки (до 60 домов), страницы — только в памяти (до 8).
Сбой ремонта оставляет основную карточку доступной и предлагает повтор; неполная карточка не сохраняется как полный успешный результат.
На Android 62963 разрешён в native PublicSources и использует очередь паспортов, независимо от объявлений. В браузере используется прямой доступ API.
В интерфейсе показаны ссылка на дополнительный источник, дата получения и предупреждение о неполноте набора.

## Ключ и кэш

`VITE_MOS_DATA_API_KEY` задаётся в `.env.local` и подставляется при сборке. По запросу пользователя ключ включается в APK.
Сборка содержит клиентский ключ; он не является серверным секретом. В ссылках-источниках, индексном JSON и ключах кэша его нет.
Android обращается к API через отменяемый native PublicSources, без localhost-посредника.
В браузере используется прямой CORS-доступ официального API.

Успешные подтверждённые сведения кэшируются локально на сутки, до 60 записей, с исходным fetchedAt.
Запись доступна по координатам и UNOM. Повторная карточка того же дома использует кэш.
Ошибки, неоднозначность и отсутствие дома не сохраняются. Очищенные сведения об одной организации
дополнительно кэшируются в памяти на сутки, максимум четыре организации. Контакты и исходные ответы не сохраняются.

## Проверка

`npm test` проверяет реальные обезличенные поля API, сопоставление UNOM, отрицательные случаи,
отсутствие выдуманных показателей, постоянный кэш и исключительное использование codoc.site для интересов.
UI-тест проверяет московскую карточку и повторное открытие на четырёх размерах экрана.
Реальная проверка `scripts/smoke-moscow.ts` подтвердила дом: Борисовская улица, 4 — 2015 год, 16 этажей.
