    Своя прогулка.
    Свой маршрут. Истории по дороге.

    Private Walks помогает исследовать город: выбрать интересные места, составить пеший маршрут, узнать историю и особенности дома, а затем сохранить настоящую прогулку вместе со схемой пути и рассказом.

    Состояние версии 1.0.10 · 18 ноября 2026 года. Документ описывает фактическую реализацию проекта private_jorney, а не обещание будущих функций. Оформление и структура основаны на HTML-спецификациях из C:\sand_temp.

    Три основных действия: найдите места вокруг выбранных точек; нажмите на любой дом, чтобы узнать о нём; включите запись и сохраните пройденный путь. Собственного серверного приложения у Private Walks нет. Возможности онлайн зависят от внешних источников.

    1. Назначение и ценность

    Подготовить прогулку

    Вместо поиска каждого места по отдельности — карта интересных точек вокруг адреса, текущего положения или нескольких выбранных опорных точек.

    Увидеть город внимательнее

    История здания, фотография, понятные сведения о доме и предложения квартир собраны в одной карточке с указанием источников.

    Сохранить личную историю

    План маршрута и запись фактической прогулки хранятся отдельно. Запись можно открыть позже: посмотреть схему и прочитать рассказ о местах по дороге.

    Слово «приватная» означает прежде всего локальное хранение планов, избранного и GPS-журнала без обязательной регистрации в самом приложении. Оно не означает полной сетевой анонимности: выбранные координаты и адреса передаются поставщикам карт, поиска и дополнительных сведений.

    3. Первый запуск и краткая инструкция

    Стартовая страница объясняет пользу приложения и ведёт к планированию и записи. Отдельная страница-подсказка знакомит с поиском интересов в области и возможностью нажать на обычный дом.

    1. Откройте планирование. Введите адрес, выберите результат поиска либо нажмите «Моё местоположение».
    2. Задайте радиус и категории. Для нескольких опорных точек поиск выполняется вокруг каждой из них.
    3. Откройте группу на карте или отдельную точку. Посмотрите карточку, добавьте точку в маршрут или в избранное.
    4. При необходимости нажмите на обычный дом на карте. Для этого дом не обязан входить в подборку интересов.
    5. Выберите минимум две точки и постройте пеший маршрут. Проверьте предупреждения о непостроенных участках.
    6. Сохраните план. Для фактической прогулки используйте отдельное действие «Начать запись» и в конце — «Завершить прогулку».
    7. Откройте запись, чтобы посмотреть схему пути и рассказ. Если часть источников не ответила, можно повторить дополнение рассказа.

    5. Поиск мест интереса

    Единственный источник подборок интересных мест — codoc.site. Citywalls, «Узнай Москву» и городские реестры дополняют карточки домов. Overpass используется для дорожного графа записи, а не как замена источника подборок.

    КатегорияНазначение
    Исторические домаПодборка зданий из CoDoc
    Историко-культурныеКультурные и исторические места
    МистическиеТематические места с соответствующим описанием источника
    РелигиозныеХрамы и другие тематические объекты
    БарыМеста для тематической прогулки
    ДостопримечательностиОбщая подборка интересов через CoDoc
    Своя точкаСлужебное обозначение точки пользователя; не отдельный сетевой фильтр

    Для каждой выбранной опорной точки выполняются запросы нужных категорий. Результаты объединяются по идентичности объекта, а не простым сложением количества ответов. Один объект может относиться к нескольким категориям.

    • Изменение категории или радиуса очищает прежнюю невыбранную выдачу сразу.
    • Изменения группируются с задержкой 400 мс; предыдущий запрос отменяется, его запоздалый ответ игнорируется.
    • Успешные категории появляются по мере готовности. Отказ одного источника категории не стирает уже полученные результаты других.
    • Общий предел ожидания поиска — 90 секунд. Он учитывает реальные медленные ответы CoDoc; искусственного ограничения в 20 секунд нет.
    • До трёх запросов категорий выполняются одновременно. Для исторических домов текущий запрос подборки использует лимит 200.

    Код: codocAreaPoiRepository.ts, areaSearchSession.ts, usePoisQuery. Пометка source: osm в старом справочнике категории не означает прямой поиск интересов через Overpass.

    6. Карта, группы и геолокация

    Карта построена на Leaflet и OpenStreetMap. Группировка снижает наложение маркеров. В группе учитываются уникальные объекты текущей выдачи.

    • Группа должна позволять перейти к полному списку входящих точек, включая совпадающие координаты и максимальный масштаб.
    • При приближении дочерние группы и отдельные маркеры представляют тот же набор объектов; число группы не должно превращаться в «застрявшую» нераскрываемую цифру.
    • После построения маршрута посторонние точки скрываются. Для их возвращения есть отдельное действие «Показать остальные точки».
    • Выбор адреса центрирует карту и закрывает мобильную панель.
    • Кнопка местоположения повторно центрирует карту после ручного перемещения; она не должна только добавлять ещё одну булавку.
    • «Начать отсюда» устанавливает выбранную точку в качестве начала и сохраняет возможность искать интересы вокруг неё.
    Геолокация устройства и определение почтового адреса — разные операции. Координаты можно получить без Photon. Адрес и ID дома определяются отдельными сервисами; отказ геокодера не должен блокировать доступный городской реестр.

    7. Планирование маршрута

    Выбранные точкиМинимум две, в заданном порядке
    →
    Пешие участкиN точек → N−1 обращений к построителю CoDoc
    →
    Локальный планГеометрия, точки, город и непостроенные участки

    Приложение строит участки между последовательными выбранными точками. Оно не заявляет автоматическое решение задачи оптимального обхода всех достопримечательностей. Графовый анализ записи прогулки — отдельный механизм и не меняет порядок выбранных точек плана.

    При отказе одного участка приложение сохраняет остальные. Пустой участок отмечается как непостроенный; визуальная пунктирная связь не считается реальным пешеходным путём и не входит в рассчитанную дистанцию успешных участков.

    Сохранённый план включает название, даты, опорные точки и радиус, фильтры, выбранные ID, снимки мест, геометрию и сведения о неудачных сегментах. В списке показаны город и названия начала/конца. Длинные названия переносятся.

    8. Избранное

    Звёздочка в карточке добавляет место в локальное избранное. Список можно отфильтровать по городу, открыть сохранённое место и удалить отдельную запись. Выбор избранного не обязан менять состав уже построенного маршрута.

    Избранное, планы и записи прогулок — три разные сущности. Удаление точки из избранного не означает удаление её из сохранённого плана или из истории фактической прогулки. Между устройствами эти данные автоматически не синхронизируются.

    Одна и та же логика доступна для точки интереса и обычного нажатия на дом. Отсутствие исторической статьи не исключает технический паспорт. Неизвестные поля и нули не превращаются в строки «0 жителей» или «0 квартир».

    Информация поступает независимо: недоступный Avito не должен скрывать паспорт, недоступный ремонт Москвы не должен скрывать этажность, а ошибка истории не должна стирать план прогулки.

    10. Санкт-Петербург

    История: Citywalls

    Объект сопоставляется по прямой ссылке или по данным карты Citywalls с проверкой координат и неоднозначности. Карточка получает до двух содержательных абзацев, фотографию здания при наличии и прямую ссылку на статью. Фотография человека из произвольного места страницы не подставляется вместо здания.

    В 1.0.10 основной путь не зависит от Photon. Для координат из обращения пользователя 59.9394057944393, 30.269812345504764 живой портал вернул ID 198090, адрес «14-я линия В.О., дом 35, литера А»; страница паспорта ответила HTTP 200.

    Запасные варианты — поиск по известному адресу и затем reverse-geocoding. Полное название «линия Васильевского острова» преобразуется в официальное «линия В.О.». Компактные корпуса и строения разворачиваются. Результат всё равно проверяется по координатам.

    11. Москва

    История: «Узнай Москву»

    Публичная карта и статьи um.mos.ru/houses/ используются для исторического описания, изображения и ссылки. Проверяются координаты и адрес, а не только похожее название.

    Адрес и технические сведения: data.mos.ru

    Если адрес уже известен и однозначно есть в локальном справочнике, приложение берёт UNOM без повторного геокодирования. Иначе сначала запрашиваются контуры зданий официального адресного реестра. Только при отсутствии однозначного результата используется Photon.

    НаборРольИспользуемые поля
    60562 · Адресный реестрНайти выбранное зданиеUNOM, адрес, тип объекта, Polygon/MultiPolygon; земельные участки исключены
    2681 · Управляющие организации и домаТехническая карточка по подтверждённому UNOMГод, минимальная/максимальная этажность, серия, подъезды, лифты, общая/жилая/нежилая площади
    62963 · Работы по капремонтуРаботы именно выбранного домаUNOM, ID записи, вид работ, год, статус, плановые и фактические даты

    Справочник основных домов содержит 34 472 ссылки на UNOM. Справочник ремонтных записей — 3714 записей для 2393 адресных кодов в версии набора 2.877. Это ссылки для поиска выбранного дома, а не новый источник мест интереса. Покрытие обновляется при обновлении справочников; наличие свежего HTTP-ответа не означает полноту истории всех московских домов.

    Как показывается ремонт

    • Работы группируются по крыше, воде и канализации, отоплению, электрике, фасаду и другим явно названным элементам.
    • Завершённые работы получают подпись с годом; даты раскрываются в подробностях.
    • План с прошедшим сроком обозначается как неподтверждённый, а не автоматически выполненный.
    • Отменённые работы не выдаются за действующий или завершённый ремонт.
    • Наличие ремонта части здания не означает полного капремонта всего дома.
    • При отказе дополнительного источника основные сведения остаются, появляется повторная загрузка ремонта.
    Чего пока нет в московской карточке: подтверждённых показателей износа, материалов лестниц и перекрытий, коммунальных квартир и состава жителей. В проверенных наборах эти сведения для выбранного дома не обнаружены. Поля пропускаются; возраст или серия не используются как доказательство.

    12. Правила понятной интерпретации

    Карточка сначала показывает короткую понятную формулировку, а исходные числа и даты — в раскрываемых подробностях. При этом нормативная оценка и условная шкала интерфейса явно разделены.

    Ссылка на применяемый документ доступна в карточке: СП 547.1325800.2025 · Росстандарт. Описание выше фиксирует правила приложения; оно не заменяет заключение специалиста.

    13. Квартиры в продаже

    Циан и Avito представлены отдельными блоками. Объявление показывается после сопоставления с выбранным домом; близость точки сама по себе не считается совпадением адреса. Угловые адреса требуют отдельной проверки.

    • Карточка содержит положительную цену, название, изображение при наличии, адрес и ссылку на площадку.
    • Аренда, снятые объявления, нулевые цены и неподтверждённые соседние дома отбрасываются.
    • Сохранены оба механизма Циана: прежний GET карты и POST поиска предложений.
    • Поиск Циана в области карты использует bbox и кеш на 10 минут. При открытии дома сначала проверяется этот кеш.
    • Avito не кешируется приложением как источник объявлений. Для Циана исключение из общего запрета кеширования объявлений — только явно согласованный кеш bbox.
    • CAPTCHA, HTTP 403 и другие ограничения показываются как ограничение источника; приложение не обещает постоянную доступность площадок.

    Телефонные номера продавцов и прочие контактные данные не нужны для карточек. Переход к объявлению открывает внешний сайт, где действуют его условия.

    14. Запись фактической прогулки

    Запись начинается явным нажатием и заканчивается другим нажатием или действием в уведомлении Android. Это отдельный сценарий: пользователь может гулять свободно, не строя план заранее.

    15. Графовый анализ и рассказ

    После устойчивого сохранения исходной записи приложение может дополнить её пешеходным графом OpenStreetMap и интересными местами. Сеть не нужна для самого факта сохранения уже полученных GPS-точек.

    1. Ограничить коридор. Выбрать представительные точки пути и запросить геометрию дорог через Overpass.
    2. Построить граф. Сохранить общие OSM node ID, пешую доступность и ограничения направления. Геометрическое пересечение без общего узла не становится перекрёстком; мосты не соединяются ошибочно.
    3. Найти кандидатов. Пространственная сетка выбирает близкие рёбра для наблюдений GPS.
    4. Оценить переходы. Ограниченный алгоритм Дейкстры оценивает возможные переходы по графу.
    5. Сопоставить последовательность. Витерби учитывает всю последовательность наблюдений, а не только начало и конец; петли и возвращения сохраняются.
    6. Расположить места. Объекты CoDoc в коридоре упорядочиваются по продвижению вдоль пути. Сторона определяется направлением движения; при большой погрешности используется «рядом».
    7. Сформировать текст. Локальные шаблоны соединяют сведения о пути и подтверждённые факты. Внешняя языковая модель не требуется; выдуманные исторические события не добавляются.

    Текущие ограничения обработки: до 600 наблюдений для сопоставления, до 200 координат коридора, пакеты до 50 координат, до шести областей поиска интересов и до 12 подробно описанных мест. Длинная прогулка может получить частичное дополнение.

    Исходные GPS-точки сохраняются независимо от сопоставления. Недоступный граф не удаляет путь и не превращает прогулку в прямую линию между двумя концами.

    16. Архив и автономный просмотр

    Сначала сохраняются исходный путь, время, расстояние и SVG-схема. Затем добавляются доступные сведения о местах и абзацы рассказа. Состояния записи: сохранена, частично дополнена, дополнена. Отчёт можно открыть, дополнить повторно или удалить.

    • Схема содержит геометрию пути и разные обозначения начала и конца.
    • Текст, координаты и схема доступны локально после сохранения.
    • Полная офлайн-подложка города не заявляется.
    • Фотографии, сохранённые только внешней ссылкой, могут требовать интернет.
    • При сбое процесса Android может потеряться последний несброшенный пакет точек. Уже записанная часть журнала восстанавливается.
    • Автоматического удаления старых прогулок нет. Удаление выполняет пользователь.

    Нативный журнал находится в noBackupFilesDir; готовые отчёты — в IndexedDB приложения. Очистка данных приложения или удаление приложения может удалить личный архив. Облачное резервирование и синхронизация не реализованы.

    Постоянные кеши проверяют структуру и срок. Ошибки, отменённые запросы и неподтверждённые дома не должны сохраняться как успешный паспорт. При недоступном localStorage используется память, но постоянное восстановление такого кеша уже не гарантируется.

    Дата получения остаётся исходной: чтение из кеша не делает сведения «полученными прямо сейчас». Временные кеши не заменяют личный архив. Разные подписчики общего запроса отменяются независимо.

    Применённые подходы

    • Порты и адаптеры: источник можно заменить реализацией соответствующего интерфейса.
    • Dependency Injection: клиенты, геокодеры, чтение страниц и хранилища передаются зависимостями; тесты используют контролируемые реализации.
    • Strategy: выбор подходящего поставщика истории и технической карточки зависит от города.
    • Facade: Android PublicSources скрывает очереди WebView за единым контрактом.
    • Cache-Aside: сначала проверяется кеш успешного результата, затем источник, затем валидация и запись.
    • Разделение ответственности: получение источника, интерпретация полей и React-отображение не объединены в один компонент.

    Это описание реализованных границ, а не заявление о полном отсутствии технического долга во всех старых модулях. Часть крупных функций и устаревших комментариев остаётся кандидатом на дальнейший рефакторинг.

    23. Приватность и сетевые границы

    • Личный GPS-журнал и архив не отправляются в собственный backend приложения: такого backend нет.
    • Для карт и источников выполняются внешние обращения. Дорожному графу передаётся ограниченный коридор координат; CoDoc — области поиска и выбранные пары точек маршрута.
    • Кеш источников хранит необходимые факты. Контракты управляющих организаций и контакты продавцов не нужны для конечной карточки.
    • Ключ московского API включён в APK по заданному требованию. Клиентский APK не может скрыть его как серверный секрет.
    • Ключ не включается в ссылки источников и публичные индексные JSON. Реальные токены не публикуются в этом документе.
    • Android backup для личных записей отключён. Это не заменяет экспорт или самостоятельную резервную копию.
    • Нет автоматического публичного профиля, ленты прогулок или облачной синхронизации. Явная передача SharedWalk — отдельное действие пользователя.
